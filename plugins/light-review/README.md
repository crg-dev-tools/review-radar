# light-review

**認知負荷を下げた PR レビュー**プラグイン。finding のリストを吐くゲート（[`isolated-review`](../isolated-review)＝フル）とは役割が別物で、TAKT も使いません。

## 収録 skill

| skill | 説明 |
|---|---|
| `light-code-review` | PR の意図を頂点に、指摘箇所の機能・実装者の意図・あるべき姿との乖離・放置した場合の影響までを前提込みで説明し、OK だった箇所もその理由付きで明示する。コードスメル中心・薄い指示。 |

## 何のためか

素の finding リストは「問題」しか言わず、読む人に前提が無い。人も LLM も「そもそもこのコードは何？作者は何をしたかった？あるべき姿は？」を毎回再構築させられ、その再構築コストが本当の負担になります。

このプラグインは前提を **PR の意図から滝で下ろす**ことでその負担を消します:

```text
このPRは何のため
  → 指摘箇所はその中のどの部分か
  → 実装者はどういう意図で
  → でも実際はこうなってて
  → あるべき姿との乖離
  → 放置の影響
```

「軽い」＝**読む人の認知負荷が軽い**であって、計算量や観点数を減らすことではありません。目的は、PR を見て人に新しい学びが残ること（OK を置いた理由が残ること）、前提不足による判断コストを軽減すること、そして **PR に draft で乗せて運用**することです。

## 前提

- `gh` CLI（PR を対象にする場合）。TAKT は不要です。

## 使い方

Claude Code で:

```text
/light-code-review        # 対象PRを確認 → PR意図の取り込み → コードスメル中心の説明レビューを生成
```

read-only。コードは変更せず、まずはレビュー文を生成するだけです（自動投稿はしません）。

## フル（isolated-review）との使い分け

| | light-review | isolated-review（フル） |
|---|---|---|
| 役割 | 前提を配る説明役 | 観点別の敵対的ゲート |
| 観点 | コードスメル中心（薄い指示） | correctness / regression / tests / security / overall |
| 出力 | 前提込みの自然言語ナラティブ（OK理由も明示） | severity 付き finding リスト |
| 分離 | なし（親セッションで実行） | 独立セッション並列＋統合セッション |
| 依存 | `gh` | TAKT |
